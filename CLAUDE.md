# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this repo is

An honours year: the thesis (`Thesis/`, LaTeX), the final seminar deck (`Seminar/`, HTML
slides), and the source of the second paper (`Paper/`, ACL LaTeX). There is no
application code, no test suite and no linter. "Building" means compiling LaTeX or
rendering the slide deck.

`HANDOFF.md` (gitignored, local only) is the detailed state-of-the-repo doc: per-slide
outline, known issues, thesis style gotchas. Read it before non-trivial work on the deck
or thesis, and update it when the deck structure changes.

## Commands

```sh
# slide deck: slide*.html -> deck.html -> deck.pdf -> deck.pptx
python3 build.py Seminar
python3 build.py Seminar --only 1,2,5      # pick slides and their order
python3 build.py Seminar --no-pptx         # also --no-pdf, --dpi, --name, --wait

# render a LaTeX table to a PNG for a slide
python3 table_png.py Paper/tables/abstention_rungs.tex \
  --out Seminar/figures/paper/tbl_abstention_rungs.png --dpi 600 --width 7.7cm

# rasterise a paper figure for a slide
pdftoppm -r 480 -png -singlefile Paper/figures/coverage.pdf Seminar/figures/paper/coverage

# thesis, from the repo root (pdflatex + bibtex, not biber)
export BSTINPUTS=".:./Thesis:" TEXINPUTS=".:./Thesis:"
pdflatex -interaction=nonstopmode Thesis/main.tex
bibtex main
pdflatex -interaction=nonstopmode Thesis/main.tex
pdflatex -interaction=nonstopmode Thesis/main.tex
```

Tools on this machine: `google-chrome`, `pdftoppm`/`pdftotext`/`pdfinfo`, `ffmpeg`,
`pdflatex`, `tesseract`. **There is no pip**, so no PIL, PyMuPDF or python-pptx. Image
work goes through `ffmpeg` and `pdftoppm`, and both scripts are standard library only.

## How the slide deck works

Each `Seminar/slideN.html` is a complete standalone page with three parts in its
`<style>`: the shared chrome, its own block starting at `/* ================= SLIDE n`,
then the print rules. `build.py` lifts the chrome off slide 1 and each slide's own block
and markup, and stitches them into `deck.html`. So:

- **Never hand-edit `deck.html`, `deck.pdf` or `deck.pptx`.** Edit slide files, rebuild,
  and commit the regenerated outputs with them.
- A change to the shared chrome has to be made in every slide file and in
  `Seminar/_chrome.html` (a chrome-only donor that `build.py` ignores).
- Each slide scopes its CSS behind `.sN` on `<div class="slide sN">`.
- **Numbering is manual.** The filename, the `SLIDE n` marker, the `.sN` class and the
  corner marker text all carry the number. Inserting or removing a slide means renaming
  and renumbering everything after it. The corner counts only the talk slides; backup
  slides show a label with no number.
- Images are embedded as base64 data URIs so the deck is self-contained. The source PNGs
  live in `Seminar/figures/`.

In practice the deck has been regenerated by throwaway Python scripts that read a slide
as a template for the chrome and write new slide files, then swapped in after a visual
check. Those scripts are not kept in the repo.

### Verifying slides

Overflow is invisible in source. After any slide edit, screenshot and look:

```sh
python3 build.py Seminar && pdftoppm -r 96 -png Seminar/deck.pdf /tmp/dk
```

That gives one 1280x720 PNG per slide. Any ink between y=660 and the gold bar, left of
the corner marker, has overflowed. A headless Chrome `--screenshot` of a single slide
file also works for a quick look, but the slide is centred in a viewport shorter than
the window, so its edges are not where you expect; don't measure from it.

### Design rules for the deck

- Styled after the IJCAI tutorial deck in `Resources/`: Calibri (Carlito as the stand-in,
  since Calibri is not installed here), bold italic titles, a gold bar top left and
  bottom right, white background, black text.
- It is a 15-minute talk: keep text minimal, a float plus a one-line claim and one or
  two short bullets. Prefer diagrams and annotated real pages over prose.
- Red `#980000` is the only highlight: class `hi` on a key phrase (always with bold),
  class `box` for annotation boxes over a figure, the varied stage in the pipeline
  strip, and the dashed box on the contents slides. One or two per slide.
- Navy `#1F4E79` is structure only: bullet dashes, rules, arrowheads, card tops.
- Annotation boxes are positioned in percent inside a wrapper sized to the image.
- The table of contents slide repeats at the start of each part with the current entry
  boxed. Publication details appear only inside that box.
- Survey slides use the survey paper's own terminology (for example "similarity-based
  retrieval", "adaptive-trajectory pipelines"), even where that is more technical.
- Changing font or font size shifts every layout. Rebuild and check the printed pages,
  not only screenshots: `pdftoppm -r 96 -png Seminar/deck.pdf out` gives 1280x720 pages.

## Where content comes from

- `Resources/survey.pdf` and `Resources/empirical.pdf` are the two papers. The thesis is
  a compilation of both.
- `Paper/acl_latex_oct.tex` is the empirical paper source. Its figures (`Paper/figures/`)
  and tables (`Paper/tables/`) are what the finding slides show. Several tables carry a
  "GENERATED, do not edit by hand" header: they come from scripts in a separate analysis
  repo, so don't patch the `.tex`.
- `Resources/method_results.tex` is the current simple-method results table.
- Sample document pages come from MMLongBench-Doc in `~/mpvrdu/.data/`. **Never write
  anything under `~/mpvrdu`**; render or copy what is needed into this repo.
- `Seminar/notes.md` holds the brief and the speaking cues per slide. Keep its slide
  numbers in step with the deck.

`LitReview/`, `Thesis_Backup/`, `Thesis_Template/` and `Practice_Seminar/` are
superseded and nothing reads from them.

## Thesis notes

Paths in `Thesis/main.tex` are root-relative (`\input{include/packages.tex}`), which
works on Overleaf with `Thesis/main.tex` as the main document. Bibliography is split
across `survey/custom.bib`, `empirical/custom.bib` and `include/custom.bib`. The heading
spacings, `headsep` and `headheight` in `Thesis/include/packages.tex` are tuned to match
a reference thesis to fractions of a point; leave them alone.

## Writing style

No em-dashes anywhere (prose, comments, slide copy, commit messages). Docs are written
plainly, like a developer explaining something to a teammate.
