General-Domain MLLMs and VRDU

Frontier general-domain MLLMs read a rendered page directly from pixels and handle single-page and short multi-page inputs reliably when resolution is sufficient. Even so, the products built on them rarely rely on page images alone.

Directly in context

“The full extracted text, plus page images for PDFs within the visual limits, is loaded into my context. I see all of it, with no retrieval step.”

On disk, via file tools

“The content isn't in my context yet. I read it on demand, either the whole thing […] or selectively […]. That's my choice per task.”

Retrieval

“This only applies to Projects, where knowledge that exceeds the context window is indexed and I search it rather than ingest it.”

Already a document pipeline

In their web interfaces and coding agents, both Anthropic and OpenAI parse an uploaded PDF for text and render it to per-page images, placing both in the model's context. That is a document-specialised pipeline, albeit a very simple one.

Its limits arrive quickly

Uploading a large document or several smaller ones soon fills the context window, and more complex document types often fail to be read at all.

The frontier is how general-domain MLLMs can be leveraged, together with the machinery built around them, to answer questions over documents the backbone cannot process directly. That machinery is the subject of MP-VRDU.
