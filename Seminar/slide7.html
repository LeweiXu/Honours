Evidence Management

The defining problem in MP-VRDU is evidence management. Performance depends not only on the capability of the backbone, but on how evidence is acquired, preserved, prioritised, and used across the whole pipeline.

Acquired

Turning the document into something the later stages can read at all.

  • page rendering
  • OCR and PDF parsers
  • element cropping
  • render resolution
  • text-layer extraction

Preserved

Deciding what survives a fixed token budget once the document will not fit.

  • per-page summary tokens
  • visual-token compression
  • recurrent memory state
  • sparse cross-page attention
  • structure-aware chunking

Prioritised

Choosing which of what survives is actually placed before the reasoner.

  • similarity retrieval
  • structural navigation
  • reranking
  • adjacent-page expansion
  • graph traversal

Used

Reasoning over what arrives, and going back for more when it is not enough.

  • prompted reasoning
  • iterative re-retrieval
  • tool calls
  • self-refinement
  • agentic decomposition

Every architecture in this section is a different answer to the same four questions. What a system can do is fixed by where it makes these decisions.
